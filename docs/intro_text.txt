1 引言
最初，我将这个大作业命名为： Secure Cloud Clipboard 即一种安
全云剪贴板。但采纳了 AI 的建议后，我将其命名为：Lightweight Cloud
Encrypted Clipboard Protocol 即 LCECP，设计目标是为开发者与学
生提供一个在多设备间同步敏感凭证时的轻量级、安全且易调试的解决方
案，避免使用商业通讯工具带来的隐私泄露与格式破坏问题。
简单来说，就是一个基于 TCP Socket 的轻量级协议，允许用户在多设
备间安全地传递敏感凭证 （如GitHub Token、 服务器SSH 密钥、 临时API
Key、代码片段等） 。
由于直接通过微信等商业软件传递敏感数据存在隐私泄露风险， 且格式
易被打乱，因此我设计了一个专用的协议来解决这个问题。
核心是客户端在上传前利用本地密钥对凭证进行加密， 服务器只存储和
中转密文，对用户的真实数据一无所知，即使服务器被攻破，用户隐私也不
会泄露。
2 问题与应用场景
2.1 痛点分析
在多设备 （台式机、 笔记本、 服务器） 间传递短文本凭证或代码片段时，
常见问题包括：
• 数据被第三方平台存储或分析；
• 传输过程中明文泄露；
• 目标格式被平台处理后失真。
2.2 未来应用场景
本项目的设计目标是最小化服务端对明文的可见性， 仅中转密文并把解
密逻辑保留在客户端，从而实现端到端加密。
因此，未来的应用场景包括但不限于：
• 开发者在不同开发环境（如本地 IDE、云服务器）间安全同步 API
Key、SSH 密钥等敏感凭证；

3 协议概览
3.1 协议头整体设计
为解决 TCP 字节流的粘包 /拆包问题，协议定义了一个固定的 12 字
节二进制协议头 Header，客户端/服务器通信流程为：先读取固定长度的
Header，再根据 Header 中的 body_len 字段读取后续正文 Body。协议头
字段包括版本号、消息类型、状态码、正文长度和保留字段，便于后续扩展
与兼容性维护。
具体协议头结构如下：
1 struct ProtocolHeader {
2 uint8_t version ; // 协 议 版 本
3 uint8_t msg_type ; // 消 息 类 型
4 uint16_t status_code ; // 状 态 码
5 uint32_t body_len ; // 正 文 长 度
6 uint32_t reserved ; // 保 留 字 段
7 }; // 协 议 头 结 构 体
3.2 协议头各个组成部分设计
对于协议版本，当前定义为 1，便于未来协议升级时进行兼容性判断；
对于消息类型，定义了 LOGIN、PUT、GET、EXIT 为客户端的四种
基本操作，也定义了 RESP 为服务器端操作；
对于状态码， 定义了200 OK、400 Bad Request 、413 Payload Too Large
等，以支持基本的状态返回和错误处理。
对于正文长度， 设置了一个合理的上限即64 KB ， 以防止恶意客户端发
送过大的数据包导致服务器内存耗尽。
对于保留字段，目前未使用，默认为 0，预留给未来协议扩展使用。

出于实验要求， 本协议未设计复杂的GUI， 而是采用了纯控制台交互的
方式， 核心文件也仅为三个python 程序：client.py、server.py 和 protocol.py，

工作量在千行以内。
对于加密算法的设计， 思路是客户端采用PBKDF2-HMAC-SHA256 将
用户密码与随机生成的 128 位盐值进行密钥派生，生成 Fernet 对称加密密
钥，对剪贴板内容进行端到端加密。服务器仅存储密文与盐值，不参与密钥
生成和解密过程， 因此无法获取用户明文数据； 而客户端凭借正确的账户密
码即可反解出明文，实现了基于 password 的端到端加密存储。
4 核心交互与状态机
4.1 交互特点
本协议采用典型的 client-server 模型，客户端通过 TCP Socket 连接服
务器进行交互。 而考虑到使用场景与协议复杂度， 本协议数据传输限制为了
半双工模式， 即客户端在发送完请求后等待服务器响应， 服务器在处理完请
求后发送响应并等待下一次请求。
对于多用户场景，本协议通过 threading 库实现了对多用户并发连接的
支持，但考虑到数据的安全与共享性，代码引入了全局线程锁，这一方面也
导致了高并发场景下的弱支持度。
4.2 状态机设计
协议的核心交互流程可以抽象为一个状态机，由于协议设计的简洁性，

5 运行方法
由于本项目采用纯控制台交互方式，运行过程较为简单。在运行前，应
确保客户端与服务器之间网络连通，并能够通过 TCP 协议建立连接。
1. 启动服务器： 在服务器主机终端中运行python server.py ， 服务器将
在预设端口（默认 9000）启动监听，等待客户端连接。
2. 启动客户端： 在客户端终端中运行python client.py ， 根据程序提示
输入用户名、密码以及相应操作编号即可完成登录、上传、获取等功
能。
3. 客户端成功连接后，可通过菜单选择以下操作：
• 1：上传加密后的剪贴板内容（PUT） ；
• 2：获取并解密剪贴板内容（GET） ；
• 3：发送心跳检测请求（PING） ；
• 4：退出客户端（EXIT） 。
客户端会将输入的凭证加密后连同 salt 一同发送给服务器，服务器仅
存储密文和 salt 并返回操作结果。用户可以在本地或其它设备上使用相同
的客户端连接服务器获取之前上传的凭证。

6 AI 使用情况
在本项目中，AI 技术主要应用于以下几个方面：
• 代码生成与优化：利用 AI 辅助生成加密相关算法，如 PBKDF2 密钥
派生和 Fernet 加密的实现代码；
• 文本、 文档撰写： 通过AI 协助设计实验文本如项目名称等和撰写实验
文档，提高设计效率和文档质量；
• 错误检测与修复： 通过AI 模型检测代码中的潜在错误和安全漏洞， 并
提供优化或修复建议。
而项目的构思、协议设计、状态机设计等核心部分则由我独立完成。
